# 流水线流程详解

> 本文档说明 `pipeline.py` 的完整执行流程、数据依赖和异常处理。

---

```
┌─────────────────────────────────────────────────────────────┐
│                     pipeline.py (主控)                       │
│                                                             │
│  ┌───────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│  │Step 1 │→│ Step 2-3  │→│Step 3.5  │→│ Step 4a  │       │
│  │BI导出 │  │ 分析计算  │  │ 飞书上表  │  │ 周报推送  │       │
```

## 二、Step-by-Step 详解

### Step 1: BI 数据导出

| 属性 | 值 |
|------|-----|
| 脚本 | `smartbi-data-cli/scripts/export_simple_report.py` |
| 技术 | Playwright Chromium 自动化 |
| 输入 | SmartBI 报表 ID + 日期范围过滤器 |
| 输出 | `海外思维学员语义分析明细.xlsx` (约 5 万行) |
| 耗时 | 3-10 分钟 |
| 失败处理 | 抛出异常，中断流水线 |

**导出过滤器：**
- 做工起始时间：本月 1 号
- 做工结束时间：昨天
- 池子：不限制（全量）

**取数策略：** 全月全量。每天从本月 1 号取到昨天，每个学员只保留最新数据。增量模式因对话可被修改/删除而不可靠。

**已知问题：** 5 万+ 行数据时 Playwright 偶发超时。缓解：`--skip-export` 复用已有文件。

---

### Step 2: 续费意向分析

| 属性 | 值 |
|------|-----|
| 脚本 | `analyze_renewal.py` |
| 输入 | Step 1 导出的 Excel |
| 输出 | `renewal_intention_{date}.xlsx` + `renewal_report_{date}.md` |
| 耗时 | 30-90 秒 |
| 失败处理 | 抛出异常，中断流水线 |

**处理流程：**
```
读取 Excel → 逐行解析对话 → 33类信号匹配 → 方案E评分 → 
等级分类 → 明细表导出(3 Sheet) → MD报告生成
```

**3 个 Sheet 结构：**
- Sheet1: 意向明细（每学员一行，含所有信号和得分）
- Sheet2: 统计汇总（按等级汇总人数/占比）
- Sheet3: LP 维度（按 LP 汇总各项指标）

---

### Step 2.5: LP 销售质量诊断

| 属性 | 值 |
|------|-----|
| 脚本 | `analyze_sales_quality.py` |
| 输入 | Step 1 导出的 Excel |
| 输出 | `renewal_quality_{date}.xlsx` |
| 阻塞性 | **非阻塞** — 失败不影响后续步骤 |

**4 个 Sheet 结构：**
- Sheet1: 每位学员的问题标签
- Sheet2: 按意向等级的问题分布
- Sheet3: 每位 LP 的问题发生统计
- Sheet4: 问题类型汇总

**检测规则：**
- 连续 ≥3 条相似消息 → 模板轰炸
- 打卡/活动消息占比 > 50% → 打卡干扰
- 客户从未回应 → 单向广播
- 跟进 <3 次即停止，距结课 >30 天 → 过早放弃

---

### Step 2.6: 池子拆分统计

| 属性 | 值 |
|------|-----|
| 脚本 | `pool_stats.py` |
| 输入 | Step 1 Excel + Step 2 结果 |
| 输出 | `pool_stats_{date}.xlsx` |
| 阻塞性 | **非阻塞** |

按 6 个池子维度统计：学员数、签单数、签单率、高意向数、风险数。

---

### Step 2.7: LP 续费绩效卡

| 属性 | 值 |
|------|-----|
| 脚本 | `lp_performance.py` |
| 输入 | Step 1 Excel + Step 2 结果 |
| 输出 | `lp_performance_{date}.xlsx` |
| 阻塞性 | **非阻塞** |

每位 LP 的续费绩效画像：学员数、签单率、覆盖率、失联率、话术多样性、退费保障等。

着色预警：覆盖率 < 30% 红色，失联 > 30% 红色。

---

### Step 2.8: 低意向原因分析

| 属性 | 值 |
|------|-----|
| 脚本 | `low_intention_analysis.py` |
| 输入 | Step 2 意向 Excel + 原始对话 |
| 输出 | `low_intention_{date}.xlsx` |
| 阻塞性 | **非阻塞** |

对低意向学员做 4 类原因归因：
- 无互动：LP 消息已读不回
- 纯观望：极简回复，无实质内容
- 意愿不足：明确表达不续/已报其他
- 负面拉低：投诉/不满/退款等

按区域 × 小组 × 原因类别交叉统计。

---

### Step 3: 小组统计 + 过程报告

| 属性 | 值 |
|------|-----|
| 脚本 | `group_stats.py` + `process_report.py` |
| 输入 | Step 1 Excel + Step 2 结果 |
| 输出 | `group_stats_{date}.xlsx` + `group_report_{date}.md` + `process_report_{date}.xlsx` |
| 失败处理 | 抛出异常，中断流水线 |

**group_stats.py：**
- 从原始数据中映射 SID 到小组
- 按小组聚合意向等级
- 生成 MD 格式小组排名报告

**process_report.py (v4)：**
- 8 组 × 7 池交叉表
- 14 列指标（两行表头）
- 自动着色（覆盖率低/失联率高红色预警）

---

### Step 3.5: 飞书上表

| 属性 | 值 |
|------|-----|
| 脚本 | `upload_feishu_sheet.py` |
| 输入 | 3 个 Excel（意向明细 + 过程分析 + 低意向分析） |
| 输出 | 飞书在线表格 URL |
| 阻塞性 | **非阻塞** |

通过 lark-cli 将数据分批上传（每批 100 行）到飞书表格。

**3 个 Sheet：**
- Sheet1「续费意向盘」：21 列意向明细
- Sheet2「续费过程分析」：14 列交叉表
- Sheet3「低意向原因分析」：11 列原因分类

---

### Step 4a: 钉钉周报推送

| 属性 | 值 |
|------|-----|
| 脚本 | `dingtalk_push.py` |
| 输入 | 多个 Excel 文件 + 飞书 URL |
| 输出 | 4 条钉钉 Markdown 消息 |

**推送顺序：**
1. 简报（意向总览 + 小组排名 + 过程分析表 + 指标说明 + 飞书链接）
2. 港澳1/2组明细（如配置）
3. LP 问题分类诊断（如质量分析可用）
4. 汇总说明

**字符截断保护：** 飞书链接放在过程分析表前面，防止 4096 字符限制截断链接。

---

### Step 4b: 钉钉日报推送

| 属性 | 值 |
|------|-----|
| 脚本 | `daily_report.py` |
| 输入 | 今日 + 昨日意向 Excel |
| 输出 | 1 条钉钉消息（或无推送） |
| 阻塞性 | **非阻塞** |

**推送逻辑：**
- 比较昨日和今日的学员意向变化
- 仅推送等级变化了的学员（升温/降温）
- 升温学员 ≤ 10 人
- 无变化时静默（不推送）
- 排除周五（避免与周报重叠）

**首日无对比数据**时降级为"首日简报"。

## 四、故障处理矩阵

| 失败步骤 | 影响范围 | 恢复方式 |
|---------|---------|---------|
| Step 1 | 全部中断 | `--skip-export` 使用已有文件重跑 |
| Step 2 | 全部中断 | 修复脚本后重跑 |
| Step 2.5 | 仅质量报告缺失 | 不影响主流程，可单独补跑 |
| Step 2.6 | 仅池子统计缺失 | 不影响主流程 |
| Step 2.7 | 仅绩效卡缺失 | 不影响主流程 |
| Step 2.8 | 仅低意向分析缺失 | 不影响主流程 |
| Step 3 | 全部中断 | 修复后重跑 |
| Step 3.5 | 飞书表格缺失 | 钉钉推送无链接，可单独补传 |
| Step 4a/b | 推送未发出 | 确认 Webhook 后手动触发 |
